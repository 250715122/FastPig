# FastPig 快速升级流程

改完代码后，把 `FastPig\FastPig.exe` 更新到最新版本，**不重新下载笔记、不重新下载模型、不重建向量索引**。

正常情况下只需要三步：退出程序、跑 `build-exe.bat`、启动验证。

---

## 为什么以前很慢

`build-exe.bat` 里有一句 `rmdir /s /q FastPig`。jpackage 要求目标目录不存在，所以必须整个删掉。但用户数据全在这个目录里：

| 目录 / 文件 | 体积 | 删掉的代价 |
|---|---|---|
| `models` | 90.6 MB | 重新下载 ONNX 向量模型 |
| `notes` | 2.2 MB | 重新从云端拉取全部 128 篇笔记 |
| `vector_index` | 1.4 MB | 全量重建向量索引，约 2-3 分钟 |
| `fastpig.db` | 0.08 MB | 笔记元数据丢失，界面里搜不到笔记 |
| `app` / `runtime` | 123 MB | 无所谓，jpackage 会重新生成 |
| `logs` | — | 无所谓 |

脚本已改为在删除前把前四项移出去、打包完再移回，所以这些代价现在都没有了。

---

## 升级步骤

### 1. 退出 FastPig.exe

**退出前先按 Ctrl+S 保存当前笔记。**

程序在运行时文件被占用，`rmdir` 会失败；而且数据库和向量索引正被写入，此时打包会得到不一致的数据。脚本开头会用 `tasklist` 检测，发现程序在跑就直接拦下来，不会走到一半才失败。

确认已退出：

```powershell
Get-Process -Name FastPig -ErrorAction SilentlyContinue
```

没有输出即可继续。注意有时会有两个 `FastPig.exe` 进程，要全部退出。

### 2. 跑打包脚本

```powershell
cd D:\tools\git\FastPig
.\build-exe.bat
```

脚本会依次输出「已保全 notes / models / vector_index / fastpig.db」和「已还原 …」。末尾有 `pause`，回车结束。

### 3. 启动并验证

启动 `FastPig\FastPig.exe`，然后检查 `FastPig\logs\fastpig.log`：

- **不应**出现 `索引结构版本低于 2` 或 `启动后台全量索引`
- `当前索引数量` 应该是几百条而不是 0
- 同步应该以 `跳过` 为主，例如 `成功 1 个, 失败 0 个, 跳过 127 个`
- 随手搜一个关键词，确认向量检索正常

日志文件启动后约 20-30 秒才写入内容，太早去看会是 0 字节，不是出错。

**2026-08-17 首次跑通的实测输出**，可作为对照基准：

```
[VectorSearch-Init] 模型已存在，开始初始化 EmbeddingService...
[VectorSearch-Init] 模型加载成功，向量维度: 512
[VectorSearch-Init] 索引初始化完成，索引目录: D:\tools\git\FastPig\FastPig\vector_index
[VectorSearch-Init] 当前索引数量: 756
[VectorSearch-Init] 初始化完成，索引数量: 756
[CloudSync-Thread] [NoteFileSync] 需要下载: 1 个, 跳过: 127 个
[CloudSync-Thread] [NoteFileSync] 下载同步完成: 成功 1 个, 失败 0 个, 跳过 127 个, 耗时 20780ms
[AutoUpload] 定时自动上传已启动，间隔 30 分钟
```

ERROR 条数 0，全程约 22 秒，没有出现全量重建。

还有一个不看日志也能判断的办法：查 `FastPig\vector_index` 里段文件的时间戳。**如果还是上次建索引的旧日期（只有 `write.lock` 是新的），就说明索引被复用了**；如果全变成刚才的时间，说明被重建了。

```powershell
Get-ChildItem FastPig\vector_index -File -Force |
    Sort-Object LastWriteTime -Descending | Select-Object -First 4 Name, LastWriteTime
```

同理，抽查几篇笔记的 `LastWriteTime` 应为原来的旧日期而不是打包时间，说明 mtime 保住了、不会触发全量重传。

## 脚本改了什么

### 开头：拦住正在运行的程序

```bat
tasklist /FI "IMAGENAME eq FastPig.exe" 2>nul | find /I "FastPig.exe" >nul
if not errorlevel 1 (
    echo FastPig.exe 正在运行，请先退出程序再打包。
    pause
    exit /b 1
)
```

### [3/5]：删除前把数据移走

用 `move` 而不是 `copy`。同盘 `move` 是重命名，**保留文件修改时间**。这一点很关键：`NoteFileSync.shouldUpload` 靠 mtime 和文件大小判断笔记有没有被改过，mtime 一变就会把 128 篇全部重新上传一遍。

移走后会校验 `FastPig` 是否真的删掉了。删不干净说明还有进程占用，此时直接还原数据并退出，不让笔记滞留在 `_data_keep` 里。

### [5/5]：打包完移回

还顺手删掉 `vector_index\write.lock`，避免上次异常退出残留的锁导致 Lucene 报 `Lock held by another program`。

### 失败也会还原

jpackage 找不到、或打包失败时会 `goto :abort`，同样调用 `:restore_data` 把数据移回去。**任何路径下笔记都不会被留在 `_data_keep` 里。**

---

## 为什么不用重新下载笔记

同步本来就是增量的，不是每次全量拉。`NoteFileSync.shouldDownloadByVersion` 的判断是：

```java
if (cloudVersion > localVersion) {
    // 只有云端版本更高才下载
    return true;
}
```

本地版本号从 `notes\.sync_meta.json` 读；即使这个文件丢了，也会用 `parseVersionFromFile` 回退到从 `note.md` 的 front matter 里读。**所以只要 `notes` 目录还在，就不会重复下载。**

上传方向同理，`shouldUpload` 比对 mtime 和 size，没改过的不传。

---

## 为什么必须保留 fastpig.db

不能只留 `notes\` 而删掉数据库。

`NoteService.rebuildIndexFromFiles()` 能从笔记文件重建 SQLite 元数据，但 `NoteFileSync` 只在 `downloadedCount.get() > 0` 时才调用它。保留笔记之后本来就无需下载，这个重建不会触发 —— 结果是数据库空着，界面里一篇笔记都搜不到。

另外注意保留的是 `FastPig\fastpig.db`（约 0.08 MB，只存元数据），不是开发目录那份（约 2.5 MB）。后者还留着早年数据迁移时的明文正文快照，对私密笔记功能是负担。

---

## 关于向量索引的 schema 版本

`LuceneVectorSearchService` 用索引目录下的 `.schema_version` 文件判断索引结构是否过期：

```java
private boolean isSchemaCurrent() {
    Path marker = indexPath.resolve(SCHEMA_FILE);   // .schema_version
    if (!Files.exists(marker)) return false;        // 文件不存在即视为过期
    return SCHEMA_VERSION == Integer.parseInt(Files.readString(marker).trim());
}
```

判定过期就会全量重建。所以：

- **保留索引目录时，`.schema_version` 必须存在且等于代码里的 `SCHEMA_VERSION`**，否则保留了也白保留，照样重建。
- 以后如果改了索引结构（字段、docId 格式等）并把 `SCHEMA_VERSION` 加一，那一次重建是必要的，跳不掉。重建完程序会自己写入新版本号，之后就不再重建。

**首次启用本流程时的一次性操作：** 老的 `FastPig\vector_index` 里没有 `.schema_version`，需要用开发目录那份（已是 v2）替换一次：

```powershell
# 确认 FastPig.exe 已退出
Remove-Item FastPig\vector_index -Recurse -Force
Copy-Item vector_index FastPig\vector_index -Recurse -Force
Remove-Item FastPig\vector_index\write.lock -ErrorAction SilentlyContinue
Get-Content FastPig\vector_index\.schema_version   # 应输出 2
```

这一步只做一次。之后每次打包由脚本自动保全，索引始终是当前版本。

## 配置文件的单向覆盖

脚本第 [5/5] 步会用**根目录**的 `config.properties` 覆盖 `FastPig\config.properties`，且不会反向同步。

也就是说，你在程序界面里改的设置（自动上传间隔、主题、主密码等）保存在 `FastPig\config.properties`，**每次重新打包都会被根目录那份覆盖掉**。

想让设置持久，二选一：

- 直接改 `D:\tools\git\FastPig\config.properties`，或
- 打包前先把 `FastPig\config.properties` 拷回根目录

主密码丢了不影响已加密笔记的恢复：解锁对话框判断能否走主密码通道，看的是笔记自身有没有主密码包裹的密钥（front matter 里的 `masterWrappedDek`），不看配置文件里的校验值。

## 备份

改脚本或做大改动前，备份一次数据（3.7 MB 左右，很快）：

```powershell
cd D:\tools\git\FastPig
$ts = Get-Date -Format "yyyyMMdd-HHmmss"
$dest = "D:\tools\git\FastPig-backups\pkg-$ts"
New-Item -ItemType Directory -Path $dest -Force | Out-Null
Copy-Item FastPig\notes        "$dest\notes" -Recurse -Force
Copy-Item FastPig\vector_index "$dest\vector_index" -Recurse -Force
Copy-Item FastPig\fastpig.db   $dest -Force
foreach ($x in @("fastpig.db-wal","fastpig.db-shm")) {
    if (Test-Path "FastPig\$x") { Copy-Item "FastPig\$x" $dest -Force }
}
Copy-Item FastPig\config.properties $dest -Force
```

`fastpig.db-wal` 要一起带走。数据库跑在 WAL 模式下，最近的提交可能还在 `-wal` 文件里没合并进主库，只拷 `fastpig.db` 会丢掉这部分。

`models` 不用备份，它和开发目录的 `models` 逐字节相同，那份就是备份。

## 出问题时

**索引又全量重建了** — 看 `FastPig\vector_index\.schema_version` 存不存在、内容是否等于代码里的 `SCHEMA_VERSION`。如果是代码改了结构并升了版本号，这次重建是应该的。

**笔记全量重新下载** — 看 `FastPig\notes\.sync_meta.json` 还在不在。

**笔记全量重新上传** — mtime 被改了。用 `copy` 代替 `move`、或从备份里 `Copy-Item` 还原都会导致这个问题（会刷新修改时间）。等它传完一次即可，不影响数据。

**Lucene 报 Lock held by another program** — 有残留的 `write.lock`，或还有 FastPig 进程在跑：

```powershell
Get-Process -Name FastPig -ErrorAction SilentlyContinue | Stop-Process -Force
Remove-Item FastPig\vector_index\write.lock -ErrorAction SilentlyContinue
```

**打包中断，`_data_keep` 目录还在** — 说明还原没跑完，手动移回去：

```powershell
Move-Item _data_keep\notes        FastPig\notes
Move-Item _data_keep\models       FastPig\models
Move-Item _data_keep\vector_index FastPig\vector_index
Move-Item _data_keep\fastpig.db   FastPig\fastpig.db
Remove-Item _data_keep -Recurse -Force
```
